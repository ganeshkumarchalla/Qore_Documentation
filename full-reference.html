Quantum Operating & Research Environment

QORE is an evidence-driven quantum development environment. Its purpose is to keep source code, circuit structure, execution controls, visual state evidence, optimization checks, diagnostics, and experiment history connected. It is built for learning, algorithm prototyping, demonstrations, and reviewable local experiments.

Quantum model

A qubit is represented by complex amplitudes. Measurement maps an unmeasured quantum state to a classical outcome with probabilities derived from amplitude magnitudes. Multi-qubit circuits create a joint state space; superposition makes several computational paths possible, interference changes their final amplitudes, and entanglement creates correlations that cannot be described as independent qubits.

QORE uses several complementary views. Distribution answers what was measured. State World provides an interactive view of basis outcomes. Bloch spheres describe reduced single-qubit states. Statevectors and amplitudes explain the ideal pre-measurement model. Unitary matrices expose a circuit transformation when measurements are removed.

Circuit authoring

QORE accepts a safe circuit-building subset instead of arbitrary Python. A program declares one circuit using QuantumCircuit, optionally creates quantum and classical registers, applies supported gate operations, adds measurements, and uses simple numeric expressions or finite loops. This intentionally rejects shell commands, filesystem access, network calls, unrestricted imports, arbitrary function execution, and dangerous Python constructs.

Start with small circuits. Establish a basis-state test, add one transformation, then add a controlled operation and measurements. Preserve explicit classical mappings when interpreting results. Qiskit displays classical bitstrings little-endian: high classical indices appear leftmost.

Simulation

Local execution is powered by Qiskit Aer. Statevector simulation calculates ideal amplitudes; shot-based execution samples measurements. Shots control statistical resolution. A seed produces repeatable pseudo-random sampling. Noise models intentionally create non-ideal behavior and should be recorded with every result. Total variation distance reports the difference between measured and ideal distributions, where zero indicates an exact match.

Quantum Lab

Quantum Lab is the primary execution surface. It exposes configuration, result tabs, metadata, warnings, and accessible raw data. Compare ideal and measured values before drawing a conclusion. Inspect timing and backend details when comparing runs. Use State World and Bloch output to form intuition, but verify conclusions numerically through counts and probabilities.

Forge

Forge evaluates circuit transformations. Gate-count or depth reductions are useful only if behavior remains equivalent. QORE validates unitary behavior and measurement mapping before a candidate is accepted. Review the original and candidate representations, metrics, tolerance, warnings, and proof result before adopting an optimization.

Ledger

The Ledger stores reproducibility evidence: source fingerprint, simulator backend, shots, seed, noise configuration, timing, timestamp, metrics, warnings, framework versions, and historical output. Export a JSON snapshot when a result needs external review. An experiment should always include its source and controls; output alone is not enough.

Runtime and integrations

QORE includes local Qiskit and Aer support, IBM Runtime client support, and selected research add-ons. Local simulation does not need cloud credentials. Remote compute, functions, and system integrations require explicit user authorization plus credentials stored only at the backend boundary. Do not place provider tokens in browser code, source control, logs, or client-side environment variables.

Security and public deployment

Public execution must be bounded. Require authentication, rate limits, request quotas, qubit and shot limits, worker timeouts, memory limits, audit logging, and abuse monitoring. Keep workers isolated. Preserve a strict secret policy. For support, collect source, project path, backend, seed, shots, terminal output, warnings, and ledger metadata—never tokens or passwords.

Troubleshooting

Parse errors usually mean unsupported source. Rewrite code into the circuit-building subset. Unexpected counts may be caused by incorrect classical mapping, too few shots, noise, or an incorrect circuit. Check the terminal first, then the bitstring convention, distribution, metadata, and source hash. Re-run with a fixed seed before comparing two configurations.
